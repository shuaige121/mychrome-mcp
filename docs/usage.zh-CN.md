# MyChrome 中文使用说明

## 安装与接入

需要 Apple Silicon Mac、macOS 13 及以上、Node.js 24 及以上、Google Chrome、Xcode Command Line Tools。当前测试依赖也支持 Node.js 20.19+ 或 22.13+，不支持更早的 Node 20/22 小版本。

```bash
git clone https://github.com/shuaige121/mychrome-mcp.git
cd mychrome-mcp
npm ci
npm run build
npm test
node src/index.js doctor
```

GitHub 私有仓库需要访问权限。2026-10-20 检查时 npm 上尚未发布本项目，当前使用源码安装。保留安装目录，让 MCP 客户端始终启动其中的 `src/index.js`。

在 Chrome 的「显示 → 开发者」开启「允许来自 Apple 事件的 JavaScript」。然后按 `doctor` 提示，给实际启动服务的终端或桌面客户端授予 Automation、Accessibility；截图识字需要 Screen Recording，可选的习惯录制需要 Input Monitoring。权限按应用区分：从终端检查通过，不代表另一个桌面客户端也有权限。

```bash
# In the checkout, choose the client you use.
claude mcp add --scope user mychrome -- node "$PWD/src/index.js"
codex mcp add mychrome -- node "$PWD/src/index.js"
```

其他 MCP 客户端配置 stdio 命令 `node /absolute/path/to/mychrome-mcp/src/index.js`。桌面客户端找不到 Node 时，使用 `command -v node` 返回的绝对路径。

Codex 的配置放在 `~/.codex/config.toml`。不要重复添加同名条目，在已有条目中设置较长的工具超时：

```toml
[mcp_servers.mychrome]
command = "node"
args = ["/absolute/path/to/mychrome-mcp/src/index.js"]
startup_timeout_sec = 30
tool_timeout_sec = 900
```

`wait_for_user` 一次最长等 10 分钟，排队也可能等待较久；客户端过早超时会打断这些流程。[官方 OpenAI MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)说明了配置位置与超时选项。配置后开启新会话，检查 `list_tabs` 是否可用。

## 日常操作

告诉 AI 网站、使用哪个账号、目标结果和提交范围。例如：

> 用我的测试账号打开练习页面，完整作答并提交，检查成绩页和历史记录是否保存。

AI 通常会打开独立 Chrome 窗口；你已有的登录态仍然可用。要换 Chrome profile，给出 profile 名称即可。进入网站之后应再次核对页面显示的账号，因为一个 profile 里也可能登录多个 Google 或网站账号。

你已经打开的页面可以直接指定给 AI。要求它先列出标签，明确 tab ID，再操作；不要依赖“最前面的标签”长期不变。

## 共用键盘鼠标

- 读取页面通常在后台完成，你可以继续用电脑。
- 点击、输入和滚动使用真实物理键鼠。接管期间有遮罩和侧栏，结束后尽量恢复原来的 App、标签和鼠标位置。
- 接管期间普通键鼠输入会被暂时拦住，不会送到页面。取消或中断后若已有部分输入送到网页，AI 应重新读页面，不能直接重复整次输入或提交。
- **连按两次 Esc** 取消当前 agent；它必须等待用户的新指示，不能自动新建计划重新接管。其他排队中的 agent 可能继续；要暂停全部操作，用菜单栏面板的「暂停 AI 操作」。
- 多 agent 的读取可并行，物理输入按队列轮流进行。一个 agent 不应代其他 agent 清理标签，也不应启动另一个不参与队列的鼠标工具。
- `task_plan` 应覆盖整项任务，例如“完成 40 题、检查并交卷”。从第一个动作起持续接管，读题、思考和题组切换时不释放键鼠；全部完成或放弃时调用一次 `task_plan({"done": true})`。
- 输入接管仍正常时，可恢复的工具错误不会自动结束整个任务。若系统中断、断连或无法确认接管状态，会释放输入并保留未完成原因；AI 必须先核对页面，不能把“接管结束”当作“试卷完成”。需要用户操作时也会释放。

第二个屏幕可以放置 agent 窗口，但整台电脑仍只有一套物理键鼠。锁屏时请先由你解锁；`wake_screen` 只能唤醒显示器。

## 侧栏显示什么

侧栏从当前会话已有的可见 assistant 消息中提取自然语言，随原消息滚动更新，包括已经展示给你的工作说明和计划。它不会再调用一个模型，也不要求 AI 为面板额外填写 `note`、`step` 或逐题完成清单；工具调用、命令代码块、工具输出和内部推理不进入侧栏。题号变化不能证明上一题已经答完，完成状态应以页面和保存结果为准。

本机 Codex app-server daemon 0.163.0 已验证真实消息逐字流入，完整消息的 hash 与原文一致。接入需要现有兼容 daemon 和已确认正在执行的 thread；thread ID 可来自 `task_plan` 的 `conversation_id`、`MYCHROME_VISIBLE_THREAD_ID` 或 Codex runtime 的 `CODEX_THREAD_ID`，不要猜测 ID 或连接其他会话。只镜像连接后产生的消息，不读取早先答复，也不另开模型任务。其他 MCP 客户端不会自动提供这条消息流；没有兼容来源时，侧栏会显示未接入，不使用生成的进度替代。

## 菜单栏面板

服务会启动菜单栏助手。点击图标，可查看任务、准备情况和本机操作记录。

原生 GUI 顶部的「操作设置」集中放置输入方式、速度、窗口位置、通知和习惯采样；「对话」页用于查找会话、看进展及回复；「网站流程」页用于保存和运行连续网页操作。三个页面都保留暂停按钮。

| 设置 | 作用 |
|---|---|
| 暂停 AI 操作 | 阻止所有会话继续操作；恢复由用户决定。暂停时 `list_tabs` 只显示 agent 自己的标签。 |
| 输入方式 | 跟随任务（默认）、逐字键盘输入、直接粘贴。用户固定的方式优先于工具参数。 |
| 操作速度 | 0.5×、0.75×、1×、1.5×、2×、3×；接管时 ↑ / ↓ 也保存到这一项。 |
| AI 的窗口放在哪 | 默认 `away`，尽量放在你未使用的屏幕；也可固定主屏、副屏或使用现有窗口。 |
| 接管前等你停手 | 默认等待键盘空闲 1.5 秒。 |
| 标签闲置关闭 | 默认 10 分钟；可延长或关闭按时间清理。 |
| 系统通知 | 提醒需要人工处理的步骤。 |
| 记录 AI 的操作 | 在本机记录操作类型、域名和结果，不记录输入正文、完整 URL 或页面标题。 |
| 保持屏幕常亮 | 可指定时间或直到任务结束。 |
| 我的操作习惯 | 可选地录制节奏并用于后续输入；是实验功能。 |

大多数设置下一次动作生效。MCP 配置中的对应 `CHROME_BRIDGE_*` 环境变量优先于面板，面板会显示该项由配置固定。

常用环境变量：

| 变量 | 值与默认行为 |
|---|---|
| `CHROME_BRIDGE_AGENT_NAME` | 面板中的 agent 名称。 |
| `CHROME_BRIDGE_AGENT_DISPLAY` | `away`（默认）、`secondary`、`main`、`off`。 |
| `CHROME_BRIDGE_IDLE_S` | 接管前键盘空闲秒数，默认 `1.5`。 |
| `CHROME_BRIDGE_INPUT_MODE` | `auto`（默认）、`keys`、`paste`。 |
| `CHROME_BRIDGE_INPUT_SPEED` | `0.5`、`0.75`、`1`（默认）、`1.5`、`2`、`3`。 |
| `CHROME_BRIDGE_TAB_TTL_MIN` | 标签闲置分钟数，默认 `10`；`0` 关闭按时间清理。 |
| `CHROME_BRIDGE_NOTIFY` | `0` 关闭系统通知，`1` 开启。 |
| `CHROME_BRIDGE_LANG` | `en` 使用英文通知与接管面板。 |
| `CHROME_BRIDGE_HOTSWAP` | `0` 关闭 worker 自动更新。 |
| `MYCHROME_VISIBLE_THREAD_ID` | 侧栏绑定的当前会话 thread ID；需要兼容的消息来源，不能自动使任意 MCP 客户端支持消息流。 |

## 密码、验证码和人工验证

AI 使用 `wait_for_user` 把控制权交给你。

标准文本输入框可传 `field` 和 `reason`：页面高亮这个框，标签标题提醒需要输入，菜单栏提供「带我去那个页面」。等待本身不会抢走你正在其他 App 里使用的键盘焦点。

输入完成后按 Return，或提交同一个表单；多行框用 ⌘+Return。工具随后重新检查页面。页面跳转也可能结束等待，AI 仍需确认登录或验证确实成功。

富文本编辑器、iframe 内输入框等不能保证高亮，可不带 `field` 等待。CAPTCHA、bot check、访问拒绝或限流由你处理，AI 不得重复重试或换工具绕过。

`wait_for_user` 不把你输入的内容放进它的回复；后续页面本身仍可能显示个人信息，截图识字也会读取可见文字。

## AI 怎样读和操作页面

`read_page` 返回页面目录、当前屏幕内容和 `[12]` 这样的编号。默认预算为 2500 token；可按 `query` 找文本、按 `sections` 展开章节，或用 `full` 读取有长度上限的整页。预算用于选择读取方式，不是所有返回内容的严格总上限。

DOM 内容过多且页面在屏幕上时，会尝试本机识字，最后才返回图片。页面在后台时不会为了读取而接管你的输入。

页面变化后编号可能失效，应再次读取。普通元素用 `click`；输入框用 `type_text`；原生下拉菜单必须用 `select_option`，不要用 `click` 打开系统菜单。屏幕上能看到但无编号的控件，可以先 `screenshot`，再按它返回的 `text_id` 或图内坐标 `click_at`。截图过期就重新截取，不能猜坐标。

下拉选择使用真实按键，并确认当前选项。键盘未选中时返回 `select_failed`，不会自动改用网页脚本写值；先读取实际选项，再决定下一步。

「跟随任务」时，`type_text` 默认按字符顺序发送真实 ASCII 按键，也可显式传 `input_mode: "paste"`。GUI 或客户端配置固定为逐字或粘贴时，用户选择优先。逐字模式的中文等非 ASCII 或不支持控制字符会在点击、输入前被拒绝，不会输入一半后自动改用粘贴。粘贴完成后恢复剪贴板，如果其他程序已改动剪贴板，则保留新内容。

工具必须在目标框确认新输入的文字才报告成功。内容没变化、输入不完整、焦点转移或读取结果不足以确认时，会返回 `input_unconfirmed` 错误；`submit: true` 不会在这种情况下继续按 Return。若确认输入后、按 Return 前焦点或内容又变了，会返回 `submit_unconfirmed`。AI 应重新读页面核对缺失的内容，不得据此把题目标成完成。

原生日期和时间框使用标准值，例如 `2026-10-20`、`14:30`、`2026-10-20T14:30`、`2026-10`、`2026-W43`。工具先验证范围与步长，再按原生控件实际呈现的分段输入，并核对最终值；分段身份无法确定时不会猜测年月日顺序。

原生日期与时间控件需要逐键输入，选择粘贴时会在操作前拒绝。`screenshot` 只读取指定 Chrome 窗口，不切标签、不占输入锁；目标标签隐藏、窗口最小化或截图期间身份改变时拒绝截图，可用 `read_page` 读取后台 DOM。

已经打开的原生下拉菜单可能挡住 Chrome 的自动化调用。`press_key(key="escape", tab=...)` 只在最近验证的窗口和页面身份仍然匹配时发送一次 Esc。若提示身份不足、任务仍持有输入或无法确认关闭，请由用户按 Esc；恢复后重新读页面，不直接继续提交。

网页 alert、confirm、prompt 会阻塞页面读取；用 `answer_dialog` 回答工具实际列出的按钮。确认框可能代表提交、离开或丢弃内容，应按用户已授权的目标选择。

## 保存和运行网站流程

在「网站流程」选定 MyChrome 连接后，可按网站查看自动记录的最近操作和重复片段。选择起止步骤或一个建议片段，填写名称保存。只接受同一会话、标签、网站和任务中的完整连续片段，最多 50 步；不能跨过失败、敏感输入或漏记步骤。

点击保存的流程可检查各步，填写本次输入参数，再点「读取标签页」并明确选择现有页面。点「运行流程」后，MyChrome 逐步使用真实键鼠执行并核对状态，步骤之间不询问模型。运行仍遵守「操作设置」里的输入方式、速度和全局暂停；不会通过 DOM 写值或脚本点击替代输入。

用「停止流程」停止该次运行；状态尚未确认时用「检查状态」，不要再次发起同一流程。完成的步数来自执行检查，不从 AI 的说明推断。流程完成也不等于整个任务已完成，提交后的业务结果仍需核对。流程阻断或部分执行后，应先检查页面，不能从头盲目重跑。

自动记录默认开启，可在此页关闭；关闭后已有记录和流程仍保留。原始输入正文和选项值不会作为参数默认值保存。没有可用 MCP 连接时，页面会明确显示未连接。更多操作、MCP 参数、nonce 和页面限制见[网站流程说明](routines.md)。

## 常见问题

| 现象 | 处理 |
|---|---|
| 找不到工具或启动失败 | 核对绝对路径、Node 版本、`npm ci` 和 `npm run build`，再重新连接 MCP。 |
| 提示权限不足 | 从启动服务的同一个应用运行 `node src/index.js doctor`，按提示开启具体权限。 |
| 等用户输入不到一分钟就断开 | 检查 MCP 客户端的 tool timeout，建议 900 秒。 |
| `stale_marker` | 页面已变，重新 `read_page` 后再选择编号。 |
| 点击后“没有可观察的变化” | 先读页面或截图确认；按钮可能已生效，不要马上再点。 |
| 文字只输入了一部分 | 读取框当前值，决定接续或在允许的情况下重填；不要整段盲目重发。 |
| 长文本输入被客户端转到后台 | 等待原调用完成；不要重发，也不要同时发起下一次输入。逐字模式耗时受文字长度和用户速度设置影响。 |
| `site_blocked` | 调用 `wait_for_user` 等待人工处理，不重复尝试或绕过。 |
| `user_cancelled` / `paused_by_user` | 停止，等待用户恢复或给出新的指示。 |
| `taken_over` | 先读取原标签确认现状；用户已明确交回时在原标签继续，意图不明时再问。不要另开入口页替代，也不擅自关闭或夺回。 |
| 目标被挡住、窗口不在前台或坐标不可靠 | 按结果提示处理 DevTools、侧栏或遮挡，再重新读取；别绕开保护直接发键鼠。 |
| 页面有 iframe 或 canvas | 尝试截图定位；仍不可达就交给用户。 |
| 原生下拉菜单已打开 | 使用工具提供的单次 Esc 恢复；无法安全恢复时由用户按 Esc。 |
| Chrome profile 选对但网站账号不对 | 在网站账号选择器里切换到已获授权的账号，再核对页面身份。 |

## 标签关闭与保留

MyChrome 记录自己打开的标签。用户自己的标签不自动清理；疑似被用户接手的 agent 标签也会保留。AI 点击打开的新标签会按来源证据登记，不能证明归属的只报告、不冒认。`list_tabs` 会给出 `ready`、`stale`、`taken_over`、`gone` 等状态和下一步建议。

如果需要保留结果给用户看，明确告诉 AI 保留页面。提交后的结果必须先核对，再决定关闭。`close_tab` 可能确认“离开页面”，所以不要用它清理尚未保存的表单。

## 更新

工作区干净时：

```bash
git pull --ff-only
npm ci
npm run build
npm test
node src/index.js doctor
```

当前 launcher 会在会话空闲时重新加载 worker JavaScript；加载失败继续用旧版本。进行中的调用和任务接管期间不切换。`src/launcher.js`、客户端配置或权限变化需要重新连接。为确认编译后的整版已生效，结束当前任务后，在客户端重新连接 MCP。

`node src/index.js restart-all --dry-run` 只查看支持的 Claude Code 终端会话重启计划；去掉 `--dry-run` 会实际操作这些终端。它不是跨所有 MCP 客户端的通用更新器。不要在其他会话正在输入或执行任务时自行强制重启。

## 开发和真机测试

`npm test` 使用隔离状态和模拟输入。`npm run test:timing` 检查时间约束。`npm run live:queue:check`、`live:focus:check`、`live:held:check`、`live:ask:check` 检查对应真机测试前提；这些检查不等于通过真机测试。

不带 `:check` 的 live 命令会控制真实 Chrome 和键鼠。运行前需要明确测试窗口和账号，确认用户已同意这轮操作。真实网站测试应分别记录：使用版本、账号角色（去标识化）、做了什么、结果是否保存、用户接手是否成功、尚未覆盖的情况。

源码、构建、离线测试、真机操作和服务器保存结果是不同证据。不要把测试输出、浏览器截图、登录态或本机数据目录直接提交到仓库。

## 本机数据与隐私

设置和面板数据在 `~/Library/Application Support/chrome-bridge-mcp/`，输入锁等运行状态在 `~/Library/Caches/chrome-bridge-mcp/`。这些是机器本地数据，不是项目源码。

MyChrome 没有 telemetry；页面照常连接网站。工具返回的页面文字、截图进入 MCP 客户端，可能由它的 AI 服务处理。分享问题时只提供脱敏后的错误码、版本、系统信息和复现步骤，不附账号数据或运行目录。
